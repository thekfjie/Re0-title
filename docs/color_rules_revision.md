# 着色规则复查与局部编辑

2026-10-11，rules v4。本轮重新查看全部 82 张参考的七张 contact sheet，并逐样本记录 96 个可见着色单元。`analysis/color_reference_review.json` 保存原文、具体出现位置、近似色彩标签和视觉角色；运行 `analysis/review_color_references.py` 重建统计。标签是视觉近似，未冒充精确 RGB、设计师意图或全部逐字框标注。

## 参考实际支持什么

单个词内部着色很常见：#5「約束」的「束」、#9「意味」的「意」、#49「咆哮」的「哮」。因此词的重要度只能帮助选词，不能要求全词同色。片假名也会只着色一段，例如 #11「ム」、#56/#72「ガー」。

#33「少女の福音」、#35「命の価値」、#38「死の味」、#55「氷炎の結末」用小连接字「の」建立局部视觉对比。#39 还有多色装饰性例外。这五张不支持“助词越重复越重要”：桥接色是视觉功能，助词的语义权重仍低。

#24 的两个「騎」分别灰/紫，#60 用「新」与第二个「英」形成跨行对照；#48 分散到汉字与假名位置。同字的各次出现可以承担不同角色。重复字符串不应该被全局替换成同一种强调色。

灰色层级、整段灰字、纹理整块和局部彩色须区分。#26/#62/#65/#70/#73/#75 没有观察到明确局部色点，其中包含白字、浅灰或发光例外；此前像素统计的“无彩色”还包含不少灰白层级标题。不能把所有无彩色理解成缺字，也不能把灰色视为强语义强调。

没有证据证明某种意义必定对应某种色相。蓝、粉、黄、绿、红等是可选的视觉关系；故事上下文、角色颜色或场景意象可能有影响，本资料不足以验证这种映射。

## 旧规则的问题与修改

旧自动模式随机抽取零色，用户难以判断是否失效；B 的强调子串会命中每个重复位置，错误计划中的「的／の」可能全部染色；同时把 semantic importance 用作颜色的唯一质量代理，使视觉连接点与语义重点混淆。旧代码还把强调词中的每个字符加入全局集合，可能放大其他位置的同字，这一处理已移除。

现在分别保留：字号用语义 importance；颜色用内容角色、词内字面位置、模型锚点、弱概念先验和视觉桥接条件。A/B 共用 `engine/accent.py` / `web/client/accent.js` 的同一决策定义，54 组固定输入通过两端一致性检查。

自动候选优先选择一个内容字；双色模式可选第二个不同内容位置。重复词默认只选一处，重复助词不选。只有较短 `AのB` 结构（最多六字、一个「の」、两个内容块）允许一类候选以「の」作视觉桥接；中文「的」不借用这个日文特例。LLM 提议仍经过相同保护条件。

“自动强调”不再随机抽取零色；“统一前景色”明确保留无局部色的结果。这是产品行为选择，不声称参考没有无彩色标题。仅有功能字/标点、无可读强调色或用户选择统一前景色时仍可能没有自动色点，结果会记录原因。

自动色对比度不足时先从当前配色选择可读强调色，找不到才恢复前景色。手动指定颜色按原值保留，低对比度给提示。前景色可自定义，强调色池支持 1–8 个任意 `#RRGGBB`；自动数量预算仍受单色/双色约束，色池有八种不意味着必须涂八种。

## 局部编辑与透明导出

结果下方逐字符选择；Shift 连选，Ctrl/Command 多选。相同字按 Unicode scalar offset 区分：`{start,end,color}`，区间 `[start,end)` 相对于最终排版文本。选择第一个「の」不会修改第二个。编辑在全部候选间保留，改标题时清除；可单独恢复或恢复全部自动色。

局部编辑直接修改 SVG glyph outline 的 fill，布局与字号不变，不调用模型或重新搜索。PNG 从同一编辑后 SVG 渲染，两个格式和参数 JSON 一致。连字共享一个轮廓时，选择其部分字符会对该轮廓着色；日文基准字体的常见单字没有这个问题。

下载区“透明背景”立即移除全画布 rect，PNG 背景 alpha=0，SVG 保留可独立使用的轮廓。透明预览用与预期画布匹配的棋盘格。颜色可读性按所选黑底/白底检查，放到另一种背景时需重新看效果。

FastAPI `/render` 接受 `custom_colors` 和 `color_overrides`，拒绝无效 HEX、越界区间及超限颜色。上传字体隔离策略不变，SVG 不内嵌字体文件。

## 本轮验证与边界

28 项 Python 与 16 项 Node 检查通过，包括具体位置、重复助词、异常模型建议、色值校验、透明 alpha 和两端规则一致性。浏览器 QA 验证手动颜色、两个同字分别着色、跨候选保留、恢复自动、三色池、透明 PNG/SVG、移动布局与 B 冻结真实计划的共同约束；`analysis/color_editor_qa.json` 保存结果，不把离线计划测试冒充新增在线调用。

重放相同 20 条真实 B 计划生成 240 张 A/B 结果，无额外模型调用。每方案 120 张：本次 seed=42 全部有一种强调色，重复助词着色违规 0、低对比自动色 0、溢出与禁则违规 0。两方案分别有两张短结构连接点候选。详细见 `analysis/color_policy_benchmark.json` 和 `experiments/live-benchmark/results.json`。

目前仍是规则代理：短桥条件、概念列表和位置偏好可以复现、审查，不能还原设计师的故事理解，也未证明审美更接近全部参考。各类角色的标签分布来自本次人工复查，不能当独立训练/测试分割。A/B 继续同时保留，没有宣布 B 更好。
