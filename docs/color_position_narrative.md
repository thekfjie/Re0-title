# 着色位置：从标题的叙事焦点到字符选择

2026-10-11。重新查看全部 82 张原参考，并补查动画官方各集介绍、长月达平的原作章节、作者活动报告及制作方活动报道。重点是“哪个具体出现位置需要不同颜色”，不是先建立角色 → HEX 的表。

范围修正：这份文档保留叙事解释作为可选语境。生成这种风格不要求输入剧情或角色；主要研究对象是字形、大小、局部色点、错位与块之间的关系。新的独立构图实验见 [visual_grammar_revision.md](visual_grammar_revision.md)。

当前更有证据的模型是：先确定标题要呈现的行动、对象、关系或转折，再选择代表它的词内字符/片段；同时检查大小、白字结构、留白与阅读节奏；最后用颜色表达突出、弱化、对照或呼应。单个 importance 不能同时承担这些决定。

没有找到制作方公开的通用“选字着色公式”。下面分开记录可直接看到的事实、可核对的剧情、以及作者视角的解释假设。叙事解释不冒充设计师意图。

## 原作者语境提供什么

长月达平在 2013-02-11 的活动报告《なんとなく設定ちらほら》中说，副标题大多在投稿时构思，偶尔使用预先准备的标题；他举了章节结尾、昴觉醒等场面的例子，并明确说人名副标题对应那个人物的回目。据此，“标题承载哪一个场面或变化”比把所有名词排序更接近这种创作出发点。这份旧报告解释创作方法，不当作当前章节规划或动画着色规范。

原作第四章 129《俺を選べ》围绕贝蒂是否能作出自己的选择展开。画面着色的是「選」，不是自称「俺」；这与把动作作为焦点的解释相容。它不证明作者亲自指定了黄色或 glyph 的位置。

原作第五章 42《最も新しい英雄と最も古い英雄》把昴的演说与莱因哈鲁特的出场连接起来。参考图弱化前句的「新」，把后句的「英」染红。更合理的解释是分别处理两段所指的对象和关系，而不是让所有「英雄」字符统一着色；具体配色意图仍是推断。

第 65 话的官方活动报道明确提到贝蒂改变了副标题。参考 068 与 069 中，同一「晩餐会」保留「餐」的局部色位，但变换色相、背景，前两字被方块盖过。因此 069 不宜只被当成普通 OCR 缺字：它有叙事性改标题的语境。生成器仍保留可见转写，冻结 Benchmark 没有补造隐藏字符。

官方各集简介适合确认对象和场景，但不一定揭示结尾转折；不能只读剧情梗概便断言标题指谁。例如参考 030《待ちかねた再会》对应第 28 话，官方简介谈到艾姬多娜与奥托，不能直接根据蓝/粉就把两处锚点认定为蕾姆/拉姆。缺乏文本证据时，保留“期待与再会的双锚点”观察即可。

## 观察到的五种用色功能

| 功能 | 参考事实 | 对选字规则的含义 |
|---|---|---|
| 叙事焦点的局部代表 | 014「病」、021「賭」、052「選」、071「君」 | 可以是对象、谓语动作、指称，不只是大名词；标题不同，焦点类型不同 |
| 词内一个字承担色点 | 005「約束」只着色「束」；009「意味」只着色「意」；027「氷結」只着色「結」；068「晩餐会」着色「餐」 | 选对词还不够；整词着色、永远词首、永远词尾都不能复用参考 |
| 两个对象或概念的对照 | 024 两个「騎」分别灰/紫；030「待」蓝与「再」粉；060 第一段「新」灰与第二段「英」红 | 需要出现位置和关系；不能全局搜索同字、同词后一起染色 |
| 构图连接与节奏 | 033、035、038、055 的「の」；048 两处「始まり」分别着色「り」「ま」 | 助词与假名并非禁用，也不自动获得高语义权重；颜色可以服务块与块的连接和重复句式的变化 |
| 压低一部分，让另一部分显现 | 051「血／臓物」暗灰、白色「愛」；054「劇場型」灰而「悪意」白；035「命」浅灰而「の」红 | 不同于基准色不等于“更重要”；白色也可以是核心，灰色的效果须结合背景、尺寸及周边色看 |

“叙事焦点”这一列是解释模型；字体轮廓、色位和重复位置是直接观察。尤其在词内选「意」还是「味」、选「約」还是「束」时，词义往往不能给唯一答案，仍需要构图和字形实验。

## 更具体的规律与反例

### 1. 稀疏色点是常态，但不是必须一个亮色

本轮补录两处显著灰色层级后，共有 98 个记录单元，其中 79 个是单字。近似颜色标签中 58 个属于明确局部色彩、38 个属于灰/灰紫/灰度变化、2 个是整块纹理效果；这些类别不是实测饱和度阈值。82 张中有 49 张记录明确局部色彩，但这不意味着另外 33 张没有视觉层级。

48 张只有一个被记录的差异字符。计数基于显著色位标注，尚不是所有 glyph 的完整颜色分割；有些整段基准色本来就是灰色。合理的默认候选预算通常较少，不能从标题越长便推导应该涂更多字。048、039 等分散或多色结构属于需要另外表达的模式。

当前系统“自动模式至少出现一个亮色”是产品行为，并非研究证实的原风格定律。需要补充灰度结构、双锚点、连接色点及无局部亮色这些有明确理由的候选，不能为了避免看起来失效而永远挑一个词首涂蓝。

### 2. 同一个词并不固定哪个字有色

「再会」在 002 中是白字，焦点落在「魔」；030 中「再」有色并与「待」成对；049 中「再会」仍白，色点在「咆哮」的「哮」。这直接反对“再会的重要度高，所以每次都给再会染色”的通用词典。

同样，048 两个「始まり」都没有把「始」染色，分别选择「り」和「ま」。相同语义词与相同色相可以使用不同字符位置。把它解释成纯语义权重是不够的；最小的可操作表示必须包含词内位置和每次出现的位置。

### 3. 作者关心关系，画面可以把关系交给一个小字

「命の価値」「死の味」「少女の福音」均把「の」作为局部色点；它在语法上仍是低权重助词，却在视觉上串起两组概念。把这一点解读为关系节点，是可实验的假设。

全样本有 32 次「の」，只有 5 次被记录着色；不能推出“有の就染色”，也不能硬性禁用所有助词。5 次包括长于现有短桥条件的 039《魔女たちの茶会》，说明只设“六字内 AのB”还会漏掉多对象场景。

### 4. 颜色与字号可能重合，但应分开决策

六张细标中，002 的「魔」、006 的「鎖」、014 的「病」等同时承担大字与色点；035 最大字面「命」却是浅灰，而小「の」为红色。两个方向都有证据，所以不能规定最高 importance 必须同时最大、最鲜艳。

颜色效果还受墨迹面积影响：巨大蓝字与小蓝假名即使使用相同色值，也不具有相同视觉重量。后续应统计色块的 ink 面积、相对位置和与白字的对比，不能只统计着色字符数。

### 5. 有些位置会被跨标题保留

056《ゴージャス・タイガー》与 072 的续篇都在「ガー」保留黄色，新增后缀没有把锚点迁往末词。068/069 则保留「餐」的位置而改变色相和画布。这两组分别说明：系列呼应可以稳定色位；叙事变化又可能只改颜色含义，不改选字。

因此角色颜色、名称锚点、章节呼应可作为上下文，但不能用“人物名一定首字上色”替代。064 的两个相邻「リ」只选第二个，077 的「ウ」也只选具体一次；词内字面位置仍要独立表示。

## 默认算法究竟错在哪一层

把明确局部色彩缩小到“只有一个着色字符且可辨认”的 40 条，当前默认 A：

- 色点落入目标词的 23/40；
- 落在目标具体字符位置的 15/40；
- 8 条属于词选到了，但词内字选错：005、018、027、031、060、064、068、077。

这是诊断，不是审美胜率；词边界使用 Sudachi B，也不是设计师的词组真值。它说明存在两个独立问题：句子层面的焦点选错，以及词内代表字符选错。只调整名词加分或汉字加分，无法同时解决。

灰色角色还有第三种错误：即使同一个字的位置命中，把参考的弱化字改成亮色也不能算成功。旧 Benchmark 的非前景色 Jaccard 将这些效果合并，适合初步位置诊断，不足以判断颜色角色正确。下一轮需分别记录 chromatic accent、muted tone、baseline/white structure、whole-title effect；不能只给每个字符 true/false。

## 从作者／编剧角度制定下一轮候选

第一步先写一句创作意图，而不是列重要词。例如《俺を選べ》可以写成“要求对方亲自作出选择”，《自称騎士と最優の騎士》可以写成“两种骑士身份并置”，《血と臓物まで愛して》可提出“将血腥对象与爱并置”作为解释假设。

然后分别确定：谁／什么是对象，哪一个动词或名词完成转折，两个对象是对照、互补还是同一身份的前后状态。最后才在这些词里选一个代表字符或短片段，并决定它是亮色、灰度弱化、桥接色点还是维持白字结构。

候选应该覆盖不同的焦点解释。例如面对「聖域の終わりと、崩壊の始まり」，可比较“两个对象并置”“终わり／始まり对照”“两个关系桥接”三种计划。没有剧情上下文时不替用户编造人物指代。给定场景摘要或明确的创作意图后，再缩小解释范围。

A 可用句法关系、谓语/祈使结构、对照、重复指称和明确输入的叙事标签生成这些计划。B 可帮助读上下文、确认指称和提出叙事焦点，但仍需要约束下的字符级锚点选择；只输出 noun 的 importance 不够。两者使用相同输入、相同上下文、相同候选角色及 Renderer，才能检验语义模型是否带来提升。

建议计划至少包含：

```json
{
  "text": "俺を選べ",
  "intent": "要求对方亲自作出选择",
  "focus_span": [2, 4],
  "units": [
    {"span": [2, 3], "role": "chromatic_accent", "reason": "用選代表选择动作"},
    {"span": [0, 1], "role": "baseline_anchor", "reason": "俺保留白字结构"}
  ],
  "relations": [{"type": "choice", "subject_span": [0, 1], "predicate_span": [2, 4]}],
  "hue_context": null
}
```

这是接口研究提案，不是已经接入的新版 planner；没有像素坐标，也没有把“白字”自动当作次要。角色色与意象色进入 hue_context 后，再决定色相。布局引擎需要根据实际字面、色块面积、位置及对比度选择方案。
